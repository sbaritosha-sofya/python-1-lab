# Система приёма и анализа сдач

Основа системы онлайн-школы, которая принимает версии сдач лабораторных работ,
валидирует их, запускает заменяемые анализаторы и ищет похожие работы.
Репозиторий содержит ЛР1 и этап А ЛР2.

## Установка

```bash
cd /home/sofya/python
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
pip install pytest
```

## Использование

### Импорт сдач

```bash
python -m school_submissions import data/submissions.jsonl
school-submissions import data/submissions.jsonl
```

Вывод — JSON с полями `accepted`, `duplicates`, `conflicts`, `errors`.

### Запуск анализатора

```bash
python -m school_submissions analyze --assignment data/assignments.json --analyzer length data/submissions.jsonl
python -m school_submissions analyze --assignment data/assignments.json --analyzer template data/submissions.jsonl
```

Если `--analyzer` не указан, запускаются все зарегистрированные анализаторы.

### Поиск похожих сдач (этап А ЛР2)

```bash
python -m school_submissions find-similar data/corpus/submissions.jsonl \
  --assignment data/corpus/lab-sort.assignment.json \
  --method token-3gram --top-k 5

python -m school_submissions find-similar data/corpus/submissions.jsonl \
  --assignment data/corpus/lab-sort.assignment.json \
  --method ast-normalized --top-k 5
```

Каждый отчёт содержит для каждой сдачи `top` кандидатов, отдельный список
`same_student_revisions`, долю неопределённых результатов в `invalid_features`
и оценку размера индекса. Пара с пустым объединением признаков получает
`score=null`; пара, где все общие признаки приходятся на разрешённый шаблон,
помечается `status=template_only`.

Корпус и его происхождение описаны в `data/corpus/README.md`. Пересборка:

```bash
python tools/build_corpus.py
```

### Оценка качества (этап Б ЛР2)

```bash
python -m school_submissions evaluate-similarity data/corpus \
  --methods token-3gram ast-normalized \
  --threshold-step 0.01 \
  --output reports/similarity_eval.json \
  --markdown reports/similarity_eval.md
```

Порог `review_required` выбирается только на `setup` по F0.5 (precision-weighted),
затем на `eval` считаются матрица ошибок, precision, recall, F1 и доля
неопределённых результатов. Отдельно показываются метрики без шаблонных пар,
срез по отношениям, согласие методов и разбор не менее трёх ошибок, включая
общий шаблон.

### Замеры и оптимизация (этап Б ЛР2)

```bash
PYTHONHASHSEED=0 python tools/benchmark.py \
  --sizes 100 1000 5000 --repeats 3 --seed 42 --query-limit 100
```

Скрипт пишет `reports/performance.json`, `reports/performance.md` и
`reports/profile.txt`. Нагрузка синтетическая и служит только для замера
времени и памяти, не для качества.

Одна обоснованная оптимизация: размер объединения считается арифметически,
без создания множества объединения, а шаблонные признаки предвычисляются в
`template_units` при построении признаков. На 1996 парах медиана сравнения
снизилась с 0.0135 с до 0.0022 с (ускорение около 6.2x), score и
`template_only` не изменились.

## Методы сравнения

- `token-3gram` — потоковая токенизация, без комментариев и служебных токенов;
  множества троек подряд идущих токенов сравниваются мерой Jaccard
  (`|пересечение| / |объединение|`). Для каждой тройки хранится до трёх
  диапазонов исходных строк.
- `ast-normalized` — разбор в AST, имена пользовательских сущностей заменяются
  на `id0`, `id1`, ... в порядке первого появления, после чего сравниваются
  структуры и наборы троек узлов. Имена атрибутов и значения констант
  сохраняются. При `SyntaxError` возвращается понятная ошибка, а не падение.

Сравниваются только разные сдачи разных студентов одного задания. Работа сама
с собой (`self_match`) и сдачи другого задания исключаются, повторные версии
одного студента вынесены в отдельный список.

## Память и потоковость

`JSONLSource` читает файл построчно, `FeatureStream` преобразует записи лениво:
на вход подаётся итератор, а не список. Полный индекс для поиска top-k всё равно
хранит признаки всех сдач: на каждую сдачу — множество троек и до трёх диапазонов
строк на тройку. Поэтому память растёт с числом токенов, и потоковое чтение само
по себе не делает индекс константным. Для учебного корпуса из 27 сдач `lab-sort`
оценка индекса — около 23 КБ для токенов и 30 КБ для AST.

## Ограничения

- Корпус синтетический и маленький; метрики на нём не переносятся на реальных
  студентов.
- Нормализация AST намеренно не трогает имена атрибутов и константы, поэтому
  две разные программы могут совпасть по структуре.
- Сходство — сигнал для ручного разбора, а не доказательство нарушения.
- Повторные версии одного студента не считаются сходством между студентами.
- Пары с разрешённым шаблоном входят в eval как отрицательные: их высокий score
  даёт ложные срабатывания, но каждая такая пара объяснена `template_only`.
- Замеры не включают конкурентность; пиковая память измерена через `tracemalloc`.

## Архитектура

- **Модель** — неизменяемый `Submission` с вычисляемым `content_hash` и `Assignment`.
- **Парсер** — преобразует сырой JSON в модель и не модифицирует вход.
- **Сервис приёма** — отличает `accepted`, `duplicate` и `conflict` по хешу.
- **Репозиторий** — in-memory хранилище сдач.
- **Источники** — `JSONLSource` (контекстный менеджер) и `InMemorySource`, реализующие `Source` Protocol.
- **Анализаторы** — `LengthAnalyzer` и `TemplateAnalyzer`, реализующие `Analyzer` Protocol.
- **Признаки** — `features.py` строит независимые от сравнения наборы признаков
  (`token-3gram`, `ast-normalized`) с диапазонами строк.
- **Сравнение** — `comparison.py` считает Jaccard, собирает evidence, отсекает
  self-match и чужие задания, ищет top-k и отдельно повторные версии студента.
- **Поток** — `pipeline.py` реализует ленивую цепочку чтение → проверка →
  признаки через `FeatureStream`.
- **Оценка** — `evaluation.py` проверяет корпус на утечку семейств, выбирает
  порог на setup, считает метрики на eval и разбирает ошибки.
- **Замеры** — `tools/benchmark.py` измеряет время и память, профилирует
  сравнение и проверяет, что оптимизация сохраняет score.
- **Реестр** — `AnalyzerRegistry` хранит фабрики анализаторов по идентификатору.
- **Сервис анализа** — выбирает анализатор из реестра без ветвления по классам.
- **CLI** — читает JSONL, повреждённая строка не останавливает обработку.
- **Доменный слой** не читает stdin и не обращается к HTTP.

## Протокол vs наследование

`Analyzer` и `Source` объявлены как `Protocol`: любой класс с нужными методами и атрибутами подходит в качестве реализации, не требуя явного наследования. Это даёт слабую связанность и позволяет легко подменять реализации в тестах и расширять систему новыми анализаторами без изменения центрального сервиса.
